# Revise

Use when the learner supplies an existing `record_type: note` LearningRecord and asks to adjust its explanation, structure, depth, examples, wording, or supported conclusions.

Follow the shared [LearningRecord revision contract](../../_shared/learning-record.md#revision-contract). Revise the same file in place, keep the user's requested change as scope, preserve still-correct content/evidence and supported lineage, then revalidate the complete Record.

When the requested edit exposes genuinely new learning that the current Record/evidence cannot support, report that gap at the revision boundary. A separate user-confirmed synthesis action may capture it later.

This branch changes the Record only. Ticket lifecycle, Map completion, synthesis integration/derived views, parent Records, and external publication remain with their owning workflows.

Done when the same path contains one contract-valid revised conceptual LearningRecord satisfying the requested change, with no duplicate Record or unrelated work item.
