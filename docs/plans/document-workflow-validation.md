# 文档交付工作流：实现与验证

## 已实现

- 实质教学先组织为完整正文，再通过 `learning-document` 提交，聊天复用正文或有链接的节选。新例子与纠错也进入正文；状态查询保持只读。
- 文档模块提供 inspect、create/append/replace commit、schema/help、recover；正文、Question 引用和提交记录使用可恢复提交。修订冲突保护手改内容，同操作重试不重复追加，保存不生成掌握证据。
- 普通 text/JSON view 展示主文档、最近提交章节与修订，以及后续手改情况。
- transition/goal 的写操作与文档提交共用锁；只读命令不初始化工作空间。CLI 提供输入 schema，避免反复猜字段。
- `install.sh --runtime-only` 不构建或替换 viewer。安装清单记录 Git 修订、dirty 标记和内容 hash；verify 只读检查漂移。暂存失败恢复原安装，保留应用包内部相对符号链接。
- 增加已知漏写/摘要化失败样本、评分器和独立回放步骤。脚本正例明确标记为评分器夹具，不冒充模型运行。

## 验证记录

本次执行结果：共享 runtime **120/120**、viewer **12/12**；`git diff --check` 无错误。最终候选版在临时目录安装生产依赖后，80 个清单文件全部通过 verify。独立审查发现的目标目录持久化、旧锁回收竞争及 start 输入契约问题已修复。

确定性测试、独立代理教学检查、教学质量判断分开报告。测试命令为：

```sh
npm test --prefix _shared
npm test --prefix viewer
git diff --check
```

测试覆盖章节增量更新、引用关联、幂等、手改冲突、中文路径、符号链接越界、恢复 journal 目标限制、跨进程锁竞争和崩溃后恢复、只读查询、非法输入、安装漂移与替换失败回滚。

实际使用生产依赖做过临时目录 runtime-only 安装，不是只测试跳过依赖的路径。没有覆盖 `~/.codex/skills`，没有改动真实雷达学习目录。

独立 GPT Sol 学习检查的来源、候选版本清单及每轮落盘快照保存在 [live-smoke](../../evals/document-delivery/live-smoke/README.md)。它是一次真实代理冒烟检查，不是“三次重复的完整行为评估”。

本次观察到：首段建文档、继续时保留旧章节、换一种解释后及时落盘、时间与 TF 说明保存、摘要不足时扩正文、状态查询不写入，均符合预期。另起无旧聊天的 Sol 子 agent 能从最终候选运行时恢复当前问题与真实已保存内容；状态查询和新会话恢复前后，全部笔记与学习状态逐字节一致。这些是代理核对结果，不冒充人工教学质量评分。

## 保证与未覆盖范围

- 提交回执证明具体文字已保存、已关联，不证明模型以后每轮都会调用工具，也不证明文档可读性。不能把所有测试通过表述为“从此绝不会漏写”。
- 确定性恢复测试包含模拟中断和子进程 SIGKILL；未模拟物理断电，不能据此承诺硬件断电级验证。
- 锁回收使用独立互斥保护，避免两个恢复进程误删新锁。若进程恰好在持有 `.learning/.document.lock-reaper` 时退出，写入会停止；须确认没有写进程后人工移除该保护目录，再恢复。不会自动猜测安全性并强行解锁。
- 安装暂存支持同步失败回滚，未承诺安装进程在任意时刻被强杀后的自动恢复；没有执行完整 Tauri 打包构建。
- 学习 schema 迁移、人工编辑，以及独立 review/practice 写入不应与学习提交并发进行；本次不重写这些独立工作流。
- 尚无修复前后同条件三次模型回放及延迟基线，未测得固定秒数提升。下一轮试用应先补这些测量，再决定是否需要宿主级回合结束检查。
