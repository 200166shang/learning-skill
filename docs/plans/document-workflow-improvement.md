# Learning Suite 文档工作流改进方案

状态：核心开发已实施并完成本次范围的验证。本文保留实施前的调查与设计依据；实际实现和验收范围以[交付验证报告](document-workflow-validation.md)为准。没有修改真实学习目录或覆盖用户已安装的 skill。

## 1. 目标与判断

用户需要的是连续学习过程中自然积累、脱离聊天也能复习的完整教材。每次都提醒保存、保存后发现只有摘要、反复切换 skill 查询进度，都属于交付失败。

首要改进：把一次有实质内容的教学视为一次文档交付。先组织同一份完整教学正文，持久化到当前主题，再展示该正文或其有链接的节选。避免独立生成聊天长文与文档摘要这两份内容。

保留已有的学习问题、递归补基础、掌握验证和复习模型。把普通教学中的文件路径、引用维护和提交检查收进一个文档模块，不增加面向用户的命令或新的学习状态机。

## 3. 用户可见的最小流程

1. 用户选定学习主题与起点后，第一次实质讲解建立或复用主题文档；探索阶段可以没有文档。
2. “继续”读取当前章节及必要来源，生成这一段完整的解释：结论、原因、必要代码、例子、适用条件与来源位置。
3. 将完整解释写入主题文章的相应章节，验证保存与关联成功。
4. 聊天显示讲解或其节选，并给准确章节链接。正文已在文档中，不要求用户再次说“同步”。节选不再额外引入未保存的推导。
5. 用户说“不知道”或提出纠错，在原章节补上新的例子、限制或修正，沿同一问题继续。
6. 询问进度时说明当前问题、主文档和最近保存位置；没有保存事实就明确说明。

内容保存与掌握验证独立。不得因文档完善自动通过验证，也不得为了填教材而自动选择下一学习问题。

文档职责固定：主题文章负责详细教材；OVERVIEW 仅提供索引与短导读；可独立复用的概念积累成熟后再拆文档。不要按每轮对话创建文件，也不要无限追加逐字聊天记录。

## 4. 最小实现设计

以下是设计时拟定的接口，现已实现 inspect/commit，另有 schema/help 和异常恢复 recover；精确参数以 CLI schema 为准。已有学习状态模型保持原样。

### A. inspect：一次读取足够上下文

`learning-document.mjs inspect <workspace>` 返回：

- 当前问题和关联文档、显式设置的主文档（若无则给候选，不随意挑一个）。
- 文档目录、目标章节文本和内容 hash；优先有限读取，必要时再展开全文。
- 本次安装的修订信息、schema 情况；不初始化、不迁移、不写入。
- 最近一次成功提交的章节和文档 hash。这个事实只叫“最近提交”，不冒充“聊天所有内容已同步”。

主文档选择可作为可选元数据保存到当前工作空间的文档记录中。它不需要新的 Topic 业务实体；旧数据继续支持多个 noteRefs，没有清晰主文档时只在首次写入时确定。

### B. commit：正文与引用一起提交

`learning-document.mjs commit <workspace> --input <draft.json>` 接受一次文档修改：

```json
{
  "questionId": "q001",
  "documentRef": "notes/小沫机器人雷达模块.md",
  "section": "时间戳和坐标系",
  "expectedRevision": "读取时返回的文档 hash",
  "markdown": "本段完整正文，包含例子、代码解释和来源",
  "operationId": "重试使用相同值"
}
```

新建文档允许明确的 create 模式和 title；章节标题必须唯一，歧义时返回候选定位，不做全篇模糊替换。第一版支持创建和替换指定章节，复杂合并仍由模型提出明确补丁，不建设通用文档编辑器。

模块内部完成：

1. 校验当前问题、文档路径、预期 hash 和草稿格式；路径定位用真实路径检查，避免越出 notes 树。
2. 合成候选 Markdown，检查 frontmatter、非空正文、相关本地文档链接；保留原有未修改章节和用户手改内容。
3. 在工作空间同一文件系统准备临时文件，对 Markdown、必要引用变更、提交记录建立可恢复事务。复用快照校验逻辑，但不要简单调用旧 transition 后宣称一起原子成功。
4. 完成提交并读取确认；失败不返回成功，崩溃后的未完成事务可检测恢复。并发写入使用锁及 expectedRevision；用户手改冲突需重读合并。
5. 返回程序生成的文档路径、章节定位、修订 hash、保存正文或预览、改变的章节。只读重试使用 operationId 避免重复追加。

提交记录只存操作标识、修订和章节等恢复所需信息，不复制一套教学状态机、不新增学习任务。文档路径只传一次，关联与显示链接从同一事实生成。

### 内容完整性：程序检查与教学评估分开

程序能检查文件存在、修订、章节、链接、事务和“保存文本与返回文本一致”；它不能仅凭字数或摘要关键词证明教学完整。

模型应直接产出完整教材段落作为 commit 输入，聊天复用已保存段落，避免另一遍摘要改写。质量标准是复习者能靠正文重建推理：概念关系、代码含义、至少必要的示例、单位与假设、容易混淆的边界、可定位来源。短而完整的解释不需要机械填六个标题。

后续回复若临时加入新的教学推导，必须同步后再宣称交付。纠错修改旧论断并解释更正原因，避免原错说法和新解释并存。

### 保证的边界

Skill 和 CLI 无法阻止模型绕过工具直接发送 final。新增 commit 也不能独立保证每轮一定调用。因此第一阶段提供“调用后可靠保存 + 行为回归降低漏调用”，不承诺绝对强制。

若真实回放仍出现漏调用，才启动宿主集成 Spike：调查实际使用环境是否有可获得完整回合及保存结果的回合结束检查接口。只有证实存在拦截能力，才设计强制检查；没有该能力就保留明确限制，不能编造 Codex hook。避免用循环监控后台补文档掩盖不完整交付。

## 5. 交付阶段与验收

| 阶段 / 建议 PR | 具体范围 | 放行条件 |
| --- | --- | --- |
| P0：固定行为基线 | 保存本次脱敏失败用例；比较工作树与安装版本；定义完整正文、先保存后回执的契约；建立回放评分表 | 未修复版本能被评分判失败；记录准确版本与模型设置；不以测试文字存在代替行为通过 |
| P1：完成最小文档交付 | 新建 document runtime/CLI；复用 parser 与 snapshot 校验；章节提交、引用关联、冲突检测、幂等、恢复；把普通 learn 路径接到 inspect/commit | 首段有真实正文；连续学习原文档增量更新；提交失败不能宣称成功；学习问题和掌握证据不变 |
| P2：真实教学回归 | 测试修复前/后的多轮行为；断开聊天后仅用文档复习；改造日常投影显示主文档与最近提交 | 例子、代码与关键因果覆盖；无强迫小测；用户无需提醒同步；新建、继续、打断恢复都通过 |

建议按 P0 → P1 → P2 放出可试用版本，P3 随后收尾。版本对齐在 P0 就做；完整安装工具改造留 P3。先把普通学习一条路径做顺，不同时重写 review/practice/viewer。

P1 文件落点：新增 `_shared/lib/learning-document-runtime.mjs` 和 `_shared/scripts/learning-document.mjs`；必要的事务封装供新旧运行逻辑共用；复用 `_shared/lib/learning-record.mjs`；更新 learn 主文件及 document/runtime 引用。日常提示只保留少量完成条件，故障细节放在工具报错和实现里。

P2 文件落点：新增文档运行测试、`evals/document-delivery/` 场景与评分；在 `_shared/lib/learning-view.mjs` 的只读投影增加主文档及最近提交。新增评估不要再强制匹配固定英语措辞或具体教学版式。

P3 文件落点：`install.sh`、CLI 帮助/参数解析、安装清单和一致性检查。读取工具不调用 ensureWorkspace；非法 intent 不留下空目录或半初始化状态。

## 6. 回归用例与衡量方式

固定行为回放至少包括：

1. 从零选“雷达数据模型”：未提醒保存时已经有可读主题文章，并关联当前问题。
2. 连续两次“继续”：同一文档保留旧章节并加入新段落，没有纯聊天新增的大段解释。
3. LaserScan 示例：正文有 -90° 到 +90°、30° 间隔、七个位置、下标 4；角度示例与代码实际弧度单位区分清楚。
4. 时间与 TF：正文包含 sec/nsec 拆分、首束测量时间含义、frame_id 是坐标系标识且变换由 TF 提供；运动例子完整。不把采样时间到接收时间直接称为纯网络延迟。
5. 用户说“不知道”：补例子到同一段落并继续，无立即重复测验。
6. 文档提交失败：不中断成假成功；下次能定位并恢复未完成写入。
7. 中文路径、重试和用户手改：链接可打开、无重复段落、冲突不静默覆盖。
8. 用户说“摘要不足”：补详细正文，不仅改 OVERVIEW。
9. 无学习新内容的状态查询：只读，无创建问题或文档。
10. 新会话恢复：能找到当前问题与实际最新正文，不靠旧聊天猜进度。

确定性测试覆盖数据与事务，不调用模型判断质量。真实代理回放使用相同来源、初始工作空间、模型及推理设置，比较修复前后；每个关键场景至少重复三次。人工抽查和内容评分须与程序检查分开报告。

试点目标：关键场景三次回放均无需用户提醒同步；保存失败时虚报成功为零；链接和恢复测试全部通过；必要因果、代码和例子均有正文落点。样本通过不等于未来绝无漏写。

性能先建立基线：记录每轮工具调用数、重复规则读取、全文重读量、首次有效教学延迟和总耗时。普通继续回合目标是一次上下文读取、必要来源读取、一次提交，不重复 Goal/start/全图检查；新材料或异常允许额外调用。不能把模型思考时延全部归因于 skill，也不能未测试就承诺固定秒数。

## 7. 当前优先级

第一批成功标准是完整正文及时交付和可独立复习。总览美化、更多状态图、新的 Topic 状态实体、自动推荐下一题都不能代替这项交付。

本次使用 `codebase-design` 的设计思路，把分散在模型调用方的顺序、文件操作与一致性检查集中进小接口；这应减少模型需要掌握的步骤，而不是再添加一层用户必须操作的工作流。
